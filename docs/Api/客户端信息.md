# API 客户端信息

所有 `/api/*` 请求必须携带客户端和设备信息请求头。普通请求只校验并传递这些
信息，不查询或更新设备表。客户端通过独立同步接口维护设备版本快照。

本文成功响应示例中的业务字段实际统一位于 `data` 中，外层包含 `code` 和
`meta`。完整规范见《API 统一响应格式》。

## 请求头

| 请求头 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| X-Client-Type | 是 | `app-ios` | `web`、`wechat-mini`、`app-ios`、`app-android` |
| X-App-Version | 是 | `1.4.2` | 对用户展示的客户端版本 |
| X-App-Build | 是 | `10402` | 内部构建号 |
| X-Platform | 是 | `ios` | `ios`、`android`、`wechat`、`web` |
| X-OS-Version | 是 | `18.2` | 操作系统或运行环境版本 |
| X-Device-ID | 是 | `019c...` | 客户端安装实例 ID，卸载重装后可以重新生成 |
| X-Channel | 是 | `appstore` | 发布渠道，例如 `appstore`、`huawei`、`xiaomi`、`wechat` |
| X-Request-ID | 否 | UUID | 请求链路 ID；缺失时由服务端生成 |

完整示例：

```text
X-Client-Type: app-ios
X-App-Version: 1.4.2
X-App-Build: 10402
X-Platform: ios
X-OS-Version: 18.2
X-Device-ID: 019c12ef-9067-7b9d-8432-7cd97c58e295
X-Channel: appstore
X-Request-ID: 019c12f1-b7f7-7ea0-9e63-25010122f8ec
```

客户端应为每个网络请求生成新的 `X-Request-ID`。发生重试时可以沿用原 Request
ID，以便服务端将多次尝试关联起来。

## 响应头

所有通过客户端信息校验的 API 响应都会返回：

```text
X-Request-ID: 019c12f1-b7f7-7ea0-9e63-25010122f8ec
Access-Control-Expose-Headers: X-Request-ID
```

客户端报告问题时应同时提供 Request ID。

## 校验错误

缺少必填请求头，或者客户端类型、平台、Request ID 格式不正确时返回 HTTP
`422`：

```json
{
  "code": 422,
  "message": "客户端信息请求头校验失败",
  "errors": {
    "client_type": [
      "X-Client-Type 字段是必须的。"
    ]
  }
}
```

## 数据记录

- `user_devices` 仅在调用 `POST /api/devices/sync` 时按 `X-Device-ID` 保存最新
  版本、系统、渠道、IP、User-Agent 和活跃时间。
- `api_request_logs` 可选保存每次请求的 Request ID、用户、设备、方法、路径、
  状态码及服务端耗时，默认关闭。
- 同步接口可匿名调用；携带有效 Sanctum Token 时会关联当前用户。

逐请求数据库日志通过环境变量控制：

```dotenv
API_REQUEST_LOG_ENABLED=false
```

默认值为 `false`。修改环境变量后，如果生产环境使用了配置缓存，需要执行：

```bash
php artisan config:cache
```

只有短期排障或确有审计需求时才建议开启。`api_request_logs` 会快速增长，开启后
应同时配置定期归档或清理策略。关闭该配置不会影响 `user_devices` 的设备版本
聚合记录，也不会影响响应中的 `X-Request-ID`。

## 同步设备信息

`POST /api/devices/sync`

请求体为空，设备信息直接使用本页约定的请求头。接口可以匿名调用；如请求携带
有效的 Sanctum Bearer Token，则设备会关联当前用户。

```text
Authorization: Bearer {access_token}
X-Client-Type: app-ios
X-App-Version: 1.4.2
X-App-Build: 10402
X-Platform: ios
X-OS-Version: 18.2
X-Device-ID: 019c12ef-9067-7b9d-8432-7cd97c58e295
X-Channel: appstore
```

成功响应：

```json
{
  "message": "设备信息同步成功",
  "device": {
    "device_id": "019c12ef-9067-7b9d-8432-7cd97c58e295",
    "client_type": "app-ios",
    "app_version": "1.4.2",
    "app_build": "10402",
    "platform": "ios",
    "os_version": "18.2",
    "channel": "appstore",
    "synced_at": "2026-07-31T08:00:00.000000Z"
  }
}
```

建议客户端在 App 启动、登录成功、切换账号、版本变化时调用，并每 24 小时兜底
同步一次。同步使用数据库原生 upsert，不进行“先查询、再更新”。
