# 体检预约 API

接口统一前缀：`/api`  
响应格式见 [响应格式](./响应格式.md)。  
需登录，鉴权见 [认证](./认证.md)（`Authorization: Bearer {access_token}`）。

相关文档：[体检公开信息](./体检公开信息.md)、[就诊人](./就诊人.md)

## 推荐调用顺序

1. `GET /api/hospital/checkup-settings` 确认开放预约与须知  
2. `GET /api/hospital/checkup-packages` → `checkup-slots` 选套餐与场次  
3. 登录后维护就诊人 `POST /api/patients`（需填写正确性别，用于套餐性别限制校验）  
4. `POST /api/checkup-orders` 提交  
5. `GET /api/checkup-orders` / `cancel` 管理预约  

## 预约单列表

`GET /api/checkup-orders`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| status | string | 否 | 预约业务状态：`pending`/`completed`/`cancelled`/`no_show` |
| payment_status | string | 否 | 支付状态：`not_required`/`unpaid`/`paid`/`refunding`/`refunded`/`closed` |
| per_page | int | 否 | 默认 15 |

预约单支付相关字段：

| 字段 | 说明 |
| --- | --- |
| status | 预约业务状态，与支付状态独立 |
| payment_status | 支付状态 |
| paid_amount | 实付金额，两位小数字符串 |
| paid_at | 支付完成时间，未支付时为 `null` |

## 提交预约

`POST /api/checkup-orders`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| patient_id | int | 是 | 当前用户的就诊人（体检人）ID |
| slot_id | int | 是 | 场次 ID（来自可约场次列表） |
| remark | string | 否 | 备注 |

成功：`201`，返回预约单（含单号 `order_no`，前缀 `CK`）。当系统已开启支付且套餐价格大于 `0` 时，`payment_status` 为 `unpaid`；否则为 `not_required`。

业务校验（失败多为 `409`）：

- 未开放在线体检预约
- 名额不足 / 套餐下架 / 超出可约天数
- 套餐性别限制与体检人不匹配
- 同一体检人重复预约同一场次
- 近期爽约超限

扣减场次 `remaining` 在数据库事务 + 行锁中完成。

## 预约单详情

`GET /api/checkup-orders/{orderNo}`

例如：`/api/checkup-orders/CK20260904120000ABCD`

## 取消预约

`POST /api/checkup-orders/{orderNo}/cancel`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| reason | string | 否 | 取消原因 |

仅 `pending` 可取消；若配置了 `cancel_hours_before`，到检日 0 点前 N 小时内不可取消。取消成功后回补名额；待支付预约的 `payment_status` 同时变为 `closed`。

## 状态枚举

### 预约单 `status`

| 值 | 说明 |
| --- | --- |
| pending | 待到检 |
| completed | 已完成 |
| cancelled | 已取消 |
| no_show | 爽约 |

### 支付 `payment_status`

| 值 | 说明 |
| --- | --- |
| not_required | 无需支付 |
| unpaid | 待支付 |
| paid | 已支付 |
| refunding | 退款中 |
| refunded | 已退款 |
| closed | 已关闭 |

### 套餐 `gender_limit`

| 值 | 说明 |
| --- | --- |
| all | 不限 |
| male | 仅男性 |
| female | 仅女性 |
