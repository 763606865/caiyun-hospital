# 挂号预约 API

接口统一前缀：`/api`  
响应格式见 [响应格式](./响应格式.md)。  
需登录，鉴权见 [认证](./认证.md)（`Authorization: Bearer {access_token}`）。

相关文档：[医院公开信息](./医院公开信息.md)、[就诊人](./就诊人.md)

## 推荐调用顺序

1. `GET /api/hospital/appointment-settings` 确认开放挂号与须知  
2. `GET /api/hospital/departments` → `doctors` → `schedules` 选号  
3. 登录后维护 `POST /api/patients`  
4. `POST /api/appointments` 提交  
5. `GET /api/appointments` / `cancel` 管理预约  

## 预约单列表

`GET /api/appointments`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| status | string | 否 | `pending`/`completed`/`cancelled`/`no_show` |
| per_page | int | 否 | 默认 15 |

## 提交挂号

`POST /api/appointments`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| patient_id | int | 是 | 当前用户的就诊人 ID |
| quota_id | int | 是 | 号源时段 ID（来自排班详情 `quotas`） |
| remark | string | 否 | 备注 |

成功：`201`，返回预约单（含单号 `appointment_no`）。

业务校验（失败多为 `409`）：

- 未开放在线挂号
- 号源不足 / 停诊 / 超出放号天数
- 同一就诊人重复预约同一号源
- 近期爽约超限

扣减号源 `remaining` 在数据库事务 + 行锁中完成。

## 预约单详情

`GET /api/appointments/{appointmentNo}`

例如：`/api/appointments/AP20260904120000ABCD`

## 取消预约

`POST /api/appointments/{appointmentNo}/cancel`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| reason | string | 否 | 取消原因 |

仅 `pending` 可取消；若配置了 `cancel_hours_before`，就诊前 N 小时内不可取消。取消成功后回补号源。

## 状态枚举

### 预约单 `status`

| 值 | 说明 |
| --- | --- |
| pending | 待就诊 |
| completed | 已完成 |
| cancelled | 已取消 |
| no_show | 爽约 |

### 排班 `status`

| 值 | 说明 |
| --- | --- |
| normal | 正常出诊 |
| suspended | 停诊 |

### 午别 `period`

| 值 | 说明 |
| --- | --- |
| morning | 上午 |
| afternoon | 下午 |
| evening | 晚上 |
