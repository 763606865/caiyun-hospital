# GitHub Actions 部署

`.github/workflows/tests.yml` 在 Pull Request 和 `main` 分支推送时运行 CI。只有 `main`
上的 CI 全部通过后才会执行生产部署；也可以从 GitHub Actions 页面手动触发。

## GitHub Environment

在仓库的 **Settings → Environments** 中创建 `production` 环境。建议开启审批保护，
并添加以下 Secrets：

| Secret | 说明 | 示例 |
| --- | --- | --- |
| `DEPLOY_HOST` | 目标服务器地址 | `oa.example.com` |
| `DEPLOY_PORT` | SSH 端口 | `22` |
| `DEPLOY_USER` | SSH 用户 | `deploy` |
| `DEPLOY_PATH` | 服务器部署根目录 | `/var/www/caiyun-oa` |
| `DEPLOY_SSH_KEY` | SSH 私钥完整内容 | `-----BEGIN ...` |
| `DEPLOY_KNOWN_HOSTS` | 服务器 SSH Host Key | `example.com ssh-ed25519 ...` |

`DEPLOY_KNOWN_HOSTS` 应从可信渠道取得。不要在工作流中通过不受信任的网络动态接受
Host Key。

在 Secrets 和服务器尚未准备好时，部署任务默认不会运行。准备完成后，在仓库
**Settings → Secrets and variables → Actions → Variables** 中添加：

```text
DEPLOY_ENABLED=true
```

删除该变量或将其改为其他值即可暂停自动部署，CI 不受影响。

## 首次部署前准备服务器

目标服务器需要安装满足项目要求的 PHP、扩展和 Web Server。Web Server 的站点根目录
应指向：

```text
/var/www/caiyun-oa/current/public
```

按照实际的 `DEPLOY_PATH` 创建共享环境文件：

```bash
mkdir -p /var/www/caiyun-oa/shared/storage
cp /path/to/production.env /var/www/caiyun-oa/shared/.env
```

SSH 用户需要拥有 `DEPLOY_PATH` 和上传临时文件的写权限。

## 发布结构

```text
DEPLOY_PATH/
├── current -> releases/{commit-sha}
├── releases/
│   └── {commit-sha}/
└── shared/
    ├── .env
    └── storage/
```

每次发布会执行数据库迁移、Admin 权限、B 端权限与 B 端菜单的幂等 Seeder，然后生成
Laravel 缓存并原子切换 `current` 软链。最后通知 Horizon 和 Octane 重载。

如果没有使用 Horizon 或 Octane，对应命令失败不会中断部署。
